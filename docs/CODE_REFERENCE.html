מילון מושגי C++ כל המונח שהוסבר בשיחה, במקום אחד

לחיצה על כל תגית ctag בכל מקום במסמך מחפשת אותה כאן ובכל הקבצים.

std::make_unique<T>(args...)

בונה אובייקט T בזיכרון דינמי (heap) ומחזיר אותו עטוף מיד ב-unique_ptr<T>. עדיף על unique_ptr<T>(new T(...)) הישן — לא נשאר רגע-ביניים שבו יש pointer גולמי בלי בעלות, מה שבטוח יותר אם קורית חריגה תוך כדי. משמש בכל rule/registry בפרויקט: std::make_unique<RookRule>() וכו'.

explicit

על קונסטרקטור עם פרמטר יחיד — מונע מהקומפיילר "להמציא" המרה משתמעת (implicit conversion) מהטיפוס של הפרמטר לטיפוס המחלקה, במקום לא צפוי. בלעדיו, קוד כמו some_fn(a_registry) היה יכול "לבנות" RuleEngine זמני בשקט. כלל אצבע: כמעט תמיד רוצים explicit על קונסטרקטור עם פרמטר בודד.

constexpr

"הערך הזה ידוע כבר בזמן קומפילציה" — חזק מ-const (שרק אומר "לא ישתנה", לא בהכרח ידוע מראש). מאפשר לקומפיילר להטמיע את הערך ישירות בקוד המתקמפל, בלי גישה לזיכרון בזמן ריצה. כל הקבועים ב-move_reasons.hpp, motion_factory.cpp וכו'.

inline

מבטיח לקומפיילר/linker שמותר למזג הגדרות זהות של אותה פונקציה/משתנה מכמה קבצי .cpp שונים, בלי שגיאת "multiple definition". נחוץ לכל פונקציה/משתנה עם הגדרה מלאה (לא רק הצהרה) שנכתבת ישירות בתוך header.

virtual / override

מסמן פונקציה שנקראת לפי הטיפוס האמיתי של האובייקט בזמן ריצה (polymorphism), לא לפי טיפוס ה-pointer/reference שדרכו קוראים לה. override במחלקה נגזרת מוודא שהיא באמת דורסת פונקציה virtual קיימת — טעות-איות בשם הופכת לשגיאת קומפילציה.

= 0 (pure virtual)

פונקציה virtual בלי מימוש בכלל. הופכת את המחלקה ל-abstract — אי אפשר ליצור ממנה מופע ישירות, רק ממחלקות נגזרות שסיפקו מימוש. זה מה שהופך IMovementRule/ICooldownPolicy ל"חוזה בלבד".

const (על מתודה)

הבטחה שהמתודה לא משנה את האובייקט שעליו קוראים לה — נאכפת בזמן קומפילציה. מאפשרת לקרוא למתודה גם על אובייקט const/const&.

& (reference)

כינוי לאובייקט קיים, לא עותק ולא pointer — בלי אפשרות ל-null, בלי תחביר *-/->. משמש כברירת מחדל בפרויקט להעברת אובייקטים "כבדים" (Board, Piece) או שאסורים-להעתקה (ostream) בלי עלות העתקה.

std::optional<T>

"אולי יש ערך מ-T, אולי אין" כטיפוס אחד. מכריח לבדוק has_value() לפני גישה. Board::piece_at, כל parse-פונקציה, ArrivalEvent::captured_piece — כולם משתמשים בזה במקום pointer/sentinel.

std::unique_ptr<T>

מצביע "חכם" עם בעלות בלעדית על אובייקט ב-heap — משחרר (delete) אותו אוטומטית כשהוא עצמו נהרס. לא ניתן להעתקה, רק להעברה (std::move). PieceRuleRegistry מחזיק כל כלל דרך unique_ptr<IMovementRule>.

std::move

לא "מעביר" שום דבר בעצמו — רק cast שמתייג ביטוי כ-rvalue, ומאפשר לקונסטרקטור/אופרטור-השמה "לגנוב" את התוכן הפנימי במקום להעתיק. הכרחי כדי להעביר unique_ptr (PieceRuleRegistry::register_rule) או להימנע מהעתקה מיותרת (ParseError, Game).

structured bindings [a, b]

מפרק pair/tuple/map-entry ישירות למשתנים בעלי-שם, בלי .first/.second. for (const auto& [row_step, col_step] : directions), for (auto& [id, ms] : cooldowns_remaining_ms_).

enum class

enum "מוגבל-scope" — חייב PieceColor::White (לא White לבד), ואין המרה שקטה ל-int. מונע התנגשויות שמות והשוואות-בטעות בין enum-ים שונים.

static_cast<T>

המרת-טיפוס מפורשת ובטוחה (בניגוד ל-C-style cast). משמש כל הזמן בין int (חתום, Position/Board) ל-size_t (בלתי-חתום, אינדקסים ל-vector).

throw / try / catch

מנגנון לדיווח שגיאה שמפסיק ריצה רגילה וקופץ ל-catch הקרוב. הכלל: throw במקום שמתגלה השגיאה (נמוך), catch במקום שיש הקשר להחליט מה לעשות (גבוה) — לא בתוך אותה פונקציה שזרקה.

vtable

טבלת מצביעי-פונקציה שכל מחלקה עם virtual מקבלת. כל אובייקט מחזיק vptr נסתר שמצביע ל-vtable של המחלקה הקונקרטית שלו — זה מה שמאפשר ל-registry.rule_for(kind).legal_destinations(...) "לקפוץ" לקוד הנכון בזמן ריצה, בלי switch.

using (alias / declaration)

שני שימושים שונים: using X = Y; יוצר כינוי-טיפוס (ArrivalEvents = vector<ArrivalEvent>); using kfc::model::PieceColor; מקצר שם ארוך לשימוש בקובץ הנוכחי בלבד.

namespace

מבודד שמות כדי שלא יתנגשו. namespace אנונימי (namespace { ... }) בתוך .cpp מגביל את הנראות לקובץ הזה בלבד — כל ה-kXxxDirections וה-tokenize המקומיים.
